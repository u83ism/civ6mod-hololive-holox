# ドキュメントの役割分担

- `README.md` = **今どうなっているか**(現状ステータス・TODO)だけを書く。実装の理由・検討した代替案・実機で踏んだ罠は書かない(`docs/design.md`を参照させる)。
- `docs/design.md` = **なぜその設計・実装にしたか**(判断の理由、検討した代替案、実機で踏んだ罠)だけを書く。「今実装済みか/実機確認済みか」という生存期間の短い現状フラグはここに書かない(README.mdと二重管理になり、どちらかを更新し忘れて食い違う)。
  - ただし過去の実機確認イベント自体(例:「2026-09-21に◯◯を実機確認した」)は、書いた時点で凍結された過去の事実であり後から古くなって嘘になることがないため、日付付きの経過記録として残してよい。
- TODO項目は`README.md`の`## TODO`に一本化する。`docs/design.md`側に別のTODOリストを作らない。
