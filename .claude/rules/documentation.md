# ドキュメントの役割分担

- `README.md` = **今どうなっているか**(現状ステータス・TODO)だけを書く。ゲームデザインの理由・検討した代替案は`docs/design.md`、実装の仕組み・実機で踏んだ罠は`docs/implementation-notes.md`、Civ6本体の公式仕様・慣習は`docs/civ6-research/vanilla-conventions.md`に書き、READMEには書かない(参照させる)。
- `docs/design.md` = **ゲームデザイン**(何をどういう狙いで作るか、判断の理由、検討した代替案)に集中して書く。Modifier名・Luaの仕組み・artdef・実機で踏んだ罠のような**実装の詳細は`docs/implementation-notes.md`**、**Civ6本体の公式仕様・慣習は`docs/civ6-research/vanilla-conventions.md`**に分け、design.mdには「個別に登録した」のような判断だけを残して参照させる(由来: 2026-10-01、本人「design.mdはゲームデザインに集中したい」)。「今実装済みか/実機確認済みか」という生存期間の短い現状フラグはここに書かない(README.mdと二重管理になり、どちらかを更新し忘れて食い違う)。
  - ただし過去の実機確認イベント自体(例:「2026-09-21に◯◯を実機確認した」)は、書いた時点で凍結された過去の事実であり後から古くなって嘘になることがないため、日付付きの経過記録として残してよい。
- TODO項目は`README.md`の`## TODO`に一本化する。`docs/design.md`側に別のTODOリストを作らない。
- `docs/design.md`に「本人判断」「採用する」「作らない」等と書くのは、本人が明言したことだけにする。AIの提案・解釈は「案」「AIの提案」と分けて書く。本人の「保留」を「不採用」と書かない。理由も本人が言っていないものを足さない(由来: 2026-10-01、忍者UUを本人が保留にしただけなのに、AIが「『のっと!』ネタと矛盾するため作らない」と書いた)。
