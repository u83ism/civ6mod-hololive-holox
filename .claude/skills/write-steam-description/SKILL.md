# write-steam-description

Steam Workshopの掲載ページに載せる紹介文を、`Text/`配下と同じ4言語(日本語/英語/簡体字中国語zh_Hans_CN/繁体字中国語zh_Hant_HK)で書き出す。

## Git管理するのは`references/template.md`だけ、`docs/steam-description/`はコピペ用の使い捨て出力

このSkillが持つ唯一のGit管理対象は`references/template.md`(日本語)。`docs/steam-description/ja.md`・`en.md`・`zh-Hans.md`・`zh-Hant.md`は`.gitignore`済みで、Steamへのコピペのためにその都度書き出すだけの使い捨てファイル。前回の内容を参照する必要はなく、リーダーごとのセクションはLOCタグから毎回機械的に導出できる(ステップ1参照)ので、コミットして残す価値がない。

自由記述部分(冒頭文・開発中です・対応言語・バランスについて・注意事項・末尾の一文)を書き直したくなったら、**`template.md`だけを直接編集する**。`docs/steam-description/`側のファイルを直接編集して終わらせない(次に書き出すときに上書きされて消える、かつGit履歴にも残らない)。

Steam Workshopの編集画面には直接書き込む手段がない(APIも自動操作もない)ため、このSkillの作業範囲は`docs/steam-description/`配下への書き出しまでで、そこから先(Steam側へのコピペ)は本人が手動で行う。Steamの説明文編集画面は言語ごとにプルダウンで切り替えて入力する方式(実機確認済み)なので、4ファイルをそれぞれ対応する言語欄に貼る。書き出したら「Steam側にもコピペしてください」と一言添えること。

## ステップ1: `docs/steam-description/ja.md`を書き出す — 新しい文章を創作せず、LOCテキストからほぼ逐語転記する

`references/template.md`のリーダーセクションの型と`Text/ja_JP/Text.xml`の該当LOCタグを比較すると、Steam説明文はゲーム内テキストの言い換えではなく、`[ICON_Xxx]`タグを取り除いただけのほぼ逐語転記だと分かる(一条莉々華の実例で検証済み)。つまりリーダーのセクションを書くときは、独自に説明文を考える必要はなく、対応するLOCタグの値を拾って組み立てるだけでよい。

新規リーダー(文明タグ`<CIV>`・指導者タグ`<LEADER>`・ユニークユニット等のタグ`<UNIT>`)を追加する場合、`Text/ja_JP/Text.xml`から以下を引用する:

| Steam説明文の要素 | 対応するLOCタグ |
|---|---|
| 文明固有能力の名前・説明 | `LOC_TRAIT_CIVILIZATION_<CIV>_NAME` / `_DESCRIPTION` |
| 指導者固有能力(通常時)の名前・説明 | `LOC_TRAIT_LEADER_<LEADER>_NAME` / `_DESCRIPTION` |
| 指導者固有能力(独占・大企業モード時)の名前・説明(該当する能力がある場合のみ) | `LOC_TRAIT_LEADER_<LEADER>_MONOPOLIES_NAME` / `_DESCRIPTION` |
| ユニークアジェンダの名前・説明 | `LOC_AGENDA_<LEADER>_NAME` / `_DESCRIPTION` |
| ユニークユニット/区域/施設/建造物の名前・副題・説明 | ユニットなら`LOC_UNIT_<UNIT>_NAME`(区域/施設/建造物なら`LOC_DISTRICT_*`/`LOC_IMPROVEMENT_*`/`LOC_BUILDING_*`)、副題は`LOC_TRAIT_CIVILIZATION_UNIT_<UNIT>_NAME`等、説明は対応する`_DESCRIPTION` |

転記時のルール:
- `[ICON_Xxx]`タグと、それに伴う前後の余分なスペースを削除する。
- タグを削除すると文がぶつ切りになる箇所(例: 「ボーナス資源は+3」で言い切ると不自然な場合に「追加で得る」を補うなど)は、事実関係・数値を一切変えない範囲でのみ、最小限の言い換えをしてよい。数値や効果の対象を変更してはならない。
- アジェンダの隠し効果(不平の減衰速度倍加など、LOCテキストには書かれていないゲームメカニクス上の注記)がある場合は、実装時のXML(`Agendas.xml`等、`implement-leader-abilities` Skillの知識)を確認し、一条莉々華セクションと同じ書き方(丸括弧で「隠し効果、〜と同じ仕組み」と注記)で追記する。存在しないことを確認せずに省略しない。
- 「不平(Grievance)」のように、このMod自体のLOCタグではなくCiv6本体の既存概念に言及する場合は、訳語を推測したり「念のため」原語を括弧書きで併記したりしない。Civ6本体のインストールフォルダ(`Sid Meier's Civilization VI/DLC/<Expansion>/Text/<Expansion>_Translations_Text.xml`等の`<Replace Tag="..." Language="...">`要素、`write-game-text` Skillの`references/lang-jp.md`が触れている統合ファイル形式と同じ。`tools/loc-lookup`で引ける)で該当するLOCタグの各言語訳を実際に確認し、確認できた訳語だけをそのまま使う(繁体字は簡体字の単純な字体変換にならないことがある。例: `不满`/簡体字 に対して繁体字は`不滿`ではなく`怨氣`)。

## ステップ2: 他3言語(`docs/steam-description/en.md`/`zh-Hans.md`/`zh-Hant.md`)を書き出す

ステップ1で書き出した`ja.md`の内容を、それぞれの言語に翻訳して書き出す。ゼロから書き起こさず、以下を使う:

- **能力名・アジェンダ名・ユニット名などの固有名詞**は、`Text/<lang>/Text.xml`(`en_US`/`zh_Hans_CN`/`zh_Hant_HK`)に既に公式ローカライズ済みの表記が存在するので、翻訳し直さずそれをそのまま使う。ここを独自に意訳すると、ゲーム内表示とSteamページで名前が食い違ってプレイヤーを混乱させる。
- **説明文の地の文**は`ja.md`の記述を翻訳する。`Text/<lang>/Text.xml`の対応する`_DESCRIPTION`(`[ICON_Xxx]`を除いたもの)が既に自然な訳文として存在するので、内容が一致するかの裏取りに使ってよい(このSkillの対象は公式ローカライズ文体ではなくWorkshopページのくだけた紹介文なので、`write-game-text` Skillの対象外)。
- **開発中です/対応言語/バランスについて等の自由記述部分**(LOCタグに存在しない、Workshopページ固有の文章)は、`ja.md`の記述を毎回翻訳する。過去に書き出した`en.md`等が残っていても(Git管理外で消し忘れているだけの場合があるので)当てにせず、`ja.md`の現在の内容から訳す。
- **中国語の記号・語彙**は`write-game-text` Skillの`references/lang-zh.md`の知見を流用する: 読点・句点・コロン・丸括弧は全角、`%`だけ半角。引用符は**簡体字がカーブ引用符`" "`、繁体字が鉤括弧「」**(日本語と同じ見た目でも別物として意識する)。数字の前にスペースを入れない。簡体字と繁体字は単純な字体変換ではなく、語彙差(用語対訳CSV参照)も踏まえて別々に書く。

## 書式: Steam独自のタグ(markdownではない)

Steamの説明文は、markdownではなくSteam独自のBBCode風タグで書式を付ける(2026-09-30、[Steam Communityの書式ヘルプ](https://steamcommunity.com/comment/ForumTopic/formattinghelp)で確認。`#`や`**`は効かない)。使うタグは次のとおり。

- 見出し: `[h2]…[/h2]`(セクション)・`[h3]…[/h3]`(能力名等)。ほかに`[h1]`もある
- 太字: `[b]…[/b]`。区切り線: `[hr][/hr]`
- 箇条書き: `[list]`の中に`[*]項目`。リンク: `[url=https://…]表示文字[/url]`。ほかに`[u]`・`[i]`・`[strike]`・`[quote]`・`[code]`・`[spoiler]`・`[noparse]`がある

Workshopの説明欄が上記のタグをすべて解釈するかは検証していない。書き出したら、Steamの編集画面のプレビューで表示を確かめてもらう。

**絵文字**は、セクション見出しの先頭に付けてよい(`➡️`開発中・`🌐`対応言語・`⚖️`バランス・`⚠️`注意事項)。ただし**国旗の絵文字(🇯🇵等)は使わない**(Windowsは国旗を描画せず「JP」という文字で表示する)。`➡`のように異体字選択子(U+FE0F)の無い絵文字は白黒の記号になることがあるので、`➡️`と付ける。4言語で同じ絵文字を使う。

## フォーマット: プレースホルダーに沿って埋める

### `ja.md`は`references/template.md`から作る

`references/template.md`に、`ja.md`の全体像(冒頭文・開発中です・対応言語・バランスについて・注意事項・リーダーごとのセクションの型・末尾の一文)を1ファイルにまとめてある(Steam独自のタグ入り)。日本語が正本言語なので、このテンプレートファイル自体も日本語。新規リーダーのセクションがファイル全体のどこに挿入されるか(注意事項ブロックの後、末尾の一文の前)を確認するときは、必ずこのファイルを見る。

`docs/steam-description/ja.md`は、書き出すたびに次のように組み立てる(このファイル自体はGit管理外なので、毎回`template.md`から作り直す前提):
- 冒頭文・開発中です・対応言語・バランスについて・注意事項は`template.md`の文面をそのまま書き出す。
- `[h2]<指導者名>(<文明名>)[/h2]`以降のプレースホルダーブロックは、実装済みリーダー1人につき1ブロック、実装順に並べて複製し、`<>`部分を対応するLOCタグの値(ステップ1の表を参照)で機械的に埋める。指導者の下の`[b]…[/b]`のキャッチフレーズは、`docs/design.md`の該当キャラクターの「キャッチフレーズ」から取る。固有区域・固有建造物・ユニークアジェンダ等、そのリーダーに存在しないブロックは省略する。日本語・中国語は`(`の前にスペースを入れない。
- 末尾の一文はそのまま書き出す(全メンバーの実装が完了したら、`template.md`側から削除する。「その他、リーダー追加のたびに見直す箇所」参照)。

### 他3言語

`en.md`・`zh-Hans.md`・`zh-Hant.md`は独立したテンプレートファイルを持たず、ステップ2の通り`ja.md`(または`template.md`)からの翻訳として都度書く。**構造(タグ・絵文字・見出しの順序・ブロックの数)は`ja.md`と完全に同じにする**。ゲーム用語のラベル(下記)は公式の対訳に合わせる(`LOC_UI_PEDIA_UNIQUE_ABILITY`=Unique Ability/固有能力/特色能力/特色能力、`LOC_LOADING_UNIQUE_DISTRICT`/`_BUILDING`=固有の区域・建造物/特色区域・特色建筑(繁体字は特色區域・特色建築)。「专属」は公式の語彙ではない)。リーダーごとのセクションは、以下の言語別プレースホルダーに沿って埋める。

**英語版(`en.md`)**: `(`の前に半角スペースが入る点が日本語版と違う。

```
[h2]<Leader Name> (<Civilization Name>)[/h2]
[b]<Tagline>[/b]

[h3]Civilization Ability "<Civilization ability name>"[/h3]
<Civilization ability description>

[h3]Leader Ability "<Leader ability name>"[/h3]
<Leader ability description>

[h3]Unique District "<District name>"[/h3]
<District description>

[h3]Unique Building "<Building name>"[/h3]
<Building description>
```

英語は公式の作文規則(`write-game-text`の`lang-en.md`)に従うと固有名詞を引用符で囲まないが、ここはゲーム内テキストではなくWorkshopの紹介文なので、日本語版の鉤括弧に対応させて`" "`で囲む(能力名を本文の中で見分けやすくするため)。

**簡体字版(`zh-Hans.md`)**: 丸括弧は全角`（ ）`(`write-game-text`の`lang-zh.md`)、`（`の前にスペースを入れない。固有名詞はカーブ引用符`“ ”`で囲む。

```
[h2]<领袖名>（<文明名>）[/h2]
[b]<标语>[/b]

[h3]文明特色能力“<文明特色能力名称>”[/h3]
<文明特色能力说明>

[h3]领袖特色能力“<领袖特色能力名称>”[/h3]
<领袖特色能力说明>

[h3]特色区域“<区域名称>”[/h3]
<区域说明>

[h3]特色建筑“<建筑名称>”[/h3]
<建筑说明>
```

**繁体字版(`zh-Hant.md`)**: 丸括弧は全角`（ ）`、`（`の前にスペースを入れない。固有名詞は鉤括弧「」で囲む(簡体字版と記号が違う点に注意)。

```
[h2]<領袖名>（<文明名>）[/h2]
[b]<標語>[/b]

[h3]文明特色能力「<文明特色能力名稱>」[/h3]
<文明特色能力說明>

[h3]領袖特色能力「<領袖特色能力名稱>」[/h3]
<領袖特色能力說明>

[h3]特色區域「<區域名稱>」[/h3]
<區域說明>

[h3]特色建築「<建築名稱>」[/h3]
<建築說明>
```

そのリーダーに存在しないブロック(指導者固有能力の独占・大企業モード版、ユニークアジェンダ、ユニークユニット等)は4言語とも省略する。存在するときは、日本語版のテンプレートに足したブロックと同じ順序・同じ書式で、各言語の公式対訳のラベルを使って追加する。

## その他、リーダー追加のたびに見直す箇所

以下はすべて`references/template.md`(日本語)を編集する。`docs/steam-description/`配下のファイルは書き出すたびに作り直される使い捨てなので、直接編集しない。

- 冒頭の「開発中です」: 実装済みリーダーの一覧を更新する。
- 全メンバーの実装が完了したら、末尾の「今後、holoXの他メンバーも...」の一文を削除する。
- 「注意事項」は、ルールセット・拡張パックの前提や既知の制限が変わったときに更新する(現在は固有区域・固有建造物が嵐の訪れのルールセット限定であること)。
- 「対応言語」は`add-language` Skillで新しい言語を追加したときだけ更新対象。通常のリーダー追加では触らない。
- 「バランスについて」は方針が変わったときに書き換える(頻度は低いはずだが、固定文として硬直させる必要はない)。

4つの言語ファイルは常に同じ構成・同じセクション数を保つこと。1つだけ書き出して終わらせず、まとめて書き出す。
