# 文明能力・指導者能力の説明文スタイルガイド(公式テキスト調査)

2026-09-19、Civ6公式(バニラ+DLC全種+拡張2本)の文明/指導者Trait説明文422件(`LOC_TRAIT_*_NAME`/`_DESCRIPTION`、うち`_DESCRIPTION`202件)をen_US/ja_JP対訳で抽出し、DLCの実際のリリース時期(2016-10のバニラ〜2023-03のLeader Pass)ごとに並べて調査した結果。**新しいTraitの説明文を書く前に、似た効果の公式テキストをここか元データから探し、テンプレとして数値だけ差し替えるのが最短ルート**(実際に公式もこれをやっている。後述)。

## 調査方法(再現手順)

Steamの`Sid Meier's Civilization VI`インストールフォルダから直接抽出した。日本語テキストは`Text/ja_JP/`のような言語別ディレクトリではなく、`<Base>_ja_JP.xml`(バニラ)や各DLCの`<DLC名>_Translations_Text.xml`(DLC)という**統合ファイル内の`<Replace Tag="..." Language="ja_JP">`要素**として格納されている(英語は`Text/en_US/`下の`<Row Tag="...">`要素、探し方が違うので注意)。

- 対象: `Base/Assets/Text/en_US/*.xml` + `Base/Assets/Text/Vanilla_ja_JP.xml` + 全DLCの`Text/en_US/*.xml`と`Text/*_Translations_Text.xml`等(en_US配下以外)
- `LOC_TRAIT_[A-Z0-9_]+`にマッチする`<Row Tag=...><Text>...</Text></Row>`(en_US)と`<Replace Tag=... Language="ja_JP"><Text>...</Text></Replace>`(ja_JP)をタグ単位で対応付け
- DLCフォルダ名から実際のリリース時期を調べてEra分類(下記「DLCリリース時期マッピング」参照)

## 発見1: 表記ルールは全時代を通してほぼ完全に一貫している

「リリース時期によるブレ」を想定して調査したが、**構造的な文体変化はほとんど無い**。202件全体で以下が例外なく(後述の少数の逸脱を除き)成立する:

- **半角/全角**: 数字・`%`・`+`/`-`・丸括弧`()`・コロン`:`はすべて**半角**。全角括弧`（）`・全角コロン`：`の使用は202件中**0件**
- **アイコン+効果+数値の結合**: `[ICON_XXX] 効果名+数値`の順で、効果名と数値の間にスペースを入れない(例: `[ICON_Production] 生産力+15%`、`[ICON_Gold] ゴールド+3`)。アイコンタグの前後には半角スペースを1つ置く
- **文末は常体・体言止め**: 「〜になる」「〜を得る」「〜する」で終えるか、数値だけで体言止め(例:「都市国家ひとつにつき文化力+5%。」)。敬体(です/ます)は基本的に使わない
- **固有名詞の鉤括弧`「」`使い分け**:
  - **付ける**: 技術・社会制度・政策・信仰/宗教名など「研究/獲得することで発動するトリガー」としての言及(例:「造船」を研究する、「重商主義」によって)、固有ユニット名(例: 固有ユニット「レッドコート」)、遺産名(例:「ハギア・ソフィア聖堂」)、固有プロジェクト名(例:「宮廷の祭典」)
  - **付けない**: 区域・建造物・資源・地形・ユニット種別・改善などの一般名詞(例: 聖地、鉱山、長槍兵)。**改善は`IMPROVEMENT_INDUSTRY`/`IMPROVEMENT_CORPORATION`(独占/大企業モード)で実機確認済み(2026-09-22)**: `KublaiKhan_Vietnam_Translations_Text_MODE.xml`のCivilopedia/チュートリアル/通知テキスト20件以上で「産業」「大企業」への鉤括弧使用は0件。同モード名自体(「独占と大企業」)や技術名(「通貨」「経済学」)には鉤括弧が付くのに、改善名にだけは付かないというトリガー系/一般名詞の区分がここでも一貫している
- **箇条書き(`[NEWLINE][ICON_Bullet]`)の見出し**: 英語同様「見出し語 + 半角コロン + スペース + 説明」の構造をそのまま踏襲する
- **複数効果の連結**: 英語が1文(ピリオド区切り)なら日本語もほぼ1文(句点区切り)に対応させる。1文内の並列要素は読点`、`で連結

### 唯一の系統的トレンド: 効果密度の上昇(数値で確認)

文体そのものではなく、**1つの能力に詰め込む効果の数**がリリース時期とともに増えている。これは今回の会話で最初に指摘された「後期の能力は複数効果を1つに押し込んでいる」という直感と一致する:

| Era | 件数 | 平均文字数(ja) | 平均アイコン数(≒効果数) | 平均文数(。の数) | アイコン数/文数 |
|---|---:|---:|---:|---:|---:|
| バニラ (2016-10) | 40 | 94.7 | 1.68 | 2.00 | 0.84 |
| 初期Civ&Scenarioパック (2016-12〜2017-10) | 56 | 100.8 | 1.80 | 2.70 | 0.67 |
| Rise and Fall (2018-02) | 21 | 120.3 | 2.29 | 2.24 | 1.02 |
| Gathering Storm (2019-02) | 34 | 142.6 | 2.65 | 3.29 | 0.81 |
| New Frontier Pass (2020-05〜2021-03) | 24 | 121.7 | 2.50 | 2.42 | 1.03 |
| Personaパック (2020年頃) | 4 | 104.5 | 1.50 | 2.75 | 0.55 |
| **Leader Pass (2022-11〜2023-03)** | 23 | **140.0** | **3.52** | **2.13** | **1.65** |

Leader Pass(直近)は文字数・アイコン数(効果数)ともバニラの約1.5倍だが、**文数はバニラ並みに少ない**。つまり「効果を増やしつつ文は増やさない」=1文の中に条件分岐や並列効果を圧縮する構文が増えている。実例(`LOC_TRAIT_LEADER_TOKUGAWA_DESCRIPTION`、Leader Pass):

> 異なる文明にまたがる交易路の産出量と観光力が-25%になるが、国内交易路は目的地の専門区域ごとに文化力+1、科学力+1、ゴールド+2をもたらす。日本の首都から6タイル以内の都市は快適性+4を受け取り、「航空技術」を研究すると区域ごとに観光力+1を受け取る。

英語原文も同じ構造(1文に"but"で対比、複数yield列挙)なので、これは日本語ローカライズ側が勝手に圧縮しているのではなく、**英語原文の設計段階からTraitあたりの効果数が増えている**ことの反映。翻訳スタイルの問題ではなく、後期ほどTrait自体がテキスト的に「盛られている」というゲームデザイン側の傾向。

## 発見2: 公式側にも表記ゆれは実在するが、リリース時期とは無関係な単発ミス

時期に紐づく体系的なブレは無い代わりに、**時期を問わず散発するtypo・コピペミス**は複数見つかった:

- アイコンタグの大文字小文字ミス: `[ICON_SCiENCE]`(正しくは`ICON_SCIENCE`)がBabylon(NFP)・Ethiopia(NFP)・Vietnam(NFP)で複数回出現。DLCをまたいで同じミスが使い回されている(コピペ元が同じ)可能性が高い
- 敬体の混入が1件だけ存在: `LOC_TRAIT_CIVILIZATION_DRAMATIC_AGE_QUESTS_DESCRIPTION`(Byzantium_Gaul、NFP)で「採用できます。」(本来「採用できる。」であるべき箇所)。同じ文の後半は常体に戻っており、単発の校正漏れと判断できる
- アイコンタグ前後の余分な半角スペース(例:「信仰力 +2」のように数値の前にもスペースが入っている)が数箇所

→ **「表記が違うから効果も違うのでは」という迷いは、実際に公式データでも一定確率で成立する(=本当にただのtypo)ケースがある**ということでもある。逆に言えば、この程度の表記ゆれは実害が無いので、自作Modでも致命的な粒度で気にしすぎる必要はない。過剰に神経質にならず、後述の「実務ルール」の粒度で揃えれば十分。

例外的に敬体だった`ICON_Bullet`見出し付きの信仰(Religion)紹介文だけは、意図的な使い分けと見られる: 「この宗教には下記の信仰があります。」という導入文だけ敬体で、その後の箇条書き本体は常体に戻る(初期Civ&Scenarioパック期に複数件確認)。これは表記ゆれではなく、**「一覧を導入する前置き文」だけ敬体にする**という一貫した使い分けだった。

## 実務ルール(このMod系列でTrait説明文を書くときに従うこと)

1. **似た効果の公式Traitを先に探す**。当たりが付けば、その日本語文をコピーして対象語(区域名・資源名など)と数値だけ差し替える。ゼロから言い回しを考えない(公式もテンプレ使い回しをしている。`DYNASTIC_CYCLE`/`TREASURE_FLEET`/`MEDITERRANEAN`/`THUNDERBOLT`等、`_EXPANSION1`/`_EXPANSION2`サフィックス違いでほぼ同一文・数値だけ差分というTraitが多数存在する)
2. **半角**: 数字・`%`・`+`/`-`・丸括弧`()`・コロン`:`。全角括弧・全角コロンは使わない
3. **アイコン+効果名+数値は詰めて書く**: `[ICON_XXX] 効果名+数値`(数値の前にスペースを入れない)
4. **鉤括弧`「」`は「トリガーとして言及される固有名詞」にだけ使う**: 技術・社会制度・政策・宗教/信仰・固有ユニット・遺産・固有プロジェクト名。区域・建造物・資源・地形などの一般名詞には付けない
5. **常体・体言止め**で統一。「〜があります」のような敬体は基本的に使わない(一覧の前置き文だけ例外あり、通常のTrait 1個の説明文では使わなくてよい)
6. 効果を複数持たせる場合、英語原文の文分割にできるだけ対応させて日本語も文を割る。1文に収めるのは「条件+ 効果」のような密接な対のときだけ(Leader Pass期のパターンを参考にしてよいが、無理に1文に圧縮する必要はない)

## 効果カテゴリ別フレーズ早見表

| 効果カテゴリ | 英語の型 | 日本語の型(実例ベース) |
|---|---|---|
| 単純な割合/固定値ボーナス | `+N% [ICON] Yield toward X` | `Xに対する[ICON] 効果名+N%` |
| 隣接ボーナス | `X tiles provide +N adjacency for Y` | `Xタイルに隣接するYは+Nの隣接ボーナスを得る` |
| 〜するたびに | `Receive Y each time you do X` | `Xするたびに、Yが手に入る` |
| 初回のみ | `When you first complete X, receive Y` | `Xを初めて完成させると、Yを得る` |
| 通常より有利な代替条件 | `..., instead of the usual -1` | `...が、通常の-1でなく+1になる` |
| 技術/社会制度解除トリガー | `Gain the Y unique unit with X technology` | `「X」の技術で固有ユニット「Y」を獲得する` |
| ターン毎の継続効果 | `+N Yield per turn` | `毎ターンY+N` / `ターン毎にY+N` |
| 条件付き数値の上書き | `+N%, rising to +M% if Z` | `Y+N%。Zの場合は+M%` |
