# ゲーム内テキストを公式の表記で書く

ゲーム内テキストを公式に合わせる作業には、大きさの違う2つがある。

- **表記合わせ(マクロ)**: 文の組み立て方・言い回し・記号の使い方を公式に合わせる。このSkillの担当
- **用語合わせ(ミクロ)**: 文中の用語(Yield名・建造物名等)を公式訳に合わせる。チャットやdocsにも関わる横断的な作業なので、Skillではなく常時読み込まれるルール`.claude/rules/game-terms.md`の担当。このSkillの手順の中でも、名詞を書くたびにそのルールに従う

公式の手本を正しく選べば、手本に含まれる用語は最初から公式のものなので、用語合わせが必要なのは自分で差し込む名詞だけになる(手順2・3)。

## 手順

**本人が日本語話者なので、日本語を確認用の原本にする。** ただし他言語は日本語文の直訳ではなく、手順1の事実と各言語の公式テンプレートから組み立て直す(日本語特有の言い回しや誤りを他言語に持ち込まないため)。これは`add-language` Skill 4節の「テキストの翻訳元」の方針と同じ。

**以下は効果を説明するテキスト(Trait/UU/UD/UB等)の手順。** 外交台詞などキャラクター性ベースのテキストは別手順(下記「フレーバーテキストの多言語展開」)。

0. **テキストの種類を決める**: Trait(文明/指導者能力)・UU・UD/UB/UI・Civilopedia等。種類ごとに公式の定型構文が違う(下記「言語共通の規則」)
1. **事実シートを作る(言語に関係なく1回だけ)**: 効果・数値・対象・条件・制限を、実装したXML(`Modifiers`/`Requirements`/`Districts`/`Buildings`等のテーブル)から拾い、「効果1: 対象=…/内容=…/数値=…/条件=…」「制限1: …」の形で書き出す。記憶や設計メモから書かない。置き換え要素(UU/UD/UB/UI)なら、置き換え元と値を突き合わせて**違うものだけ**を洗い出す。この事実シートが、以降のすべての言語と検査の基準になる(日本語は基準ではない)
2. **日本語を書く**(完成済みなら書かず、事実シートと突き合わせて検算する)
   1. 同じ種類の公式テキストを手本として探す(`tools/loc-lookup`、例: `npm run lookup -- "^LOC_BUILDING_(MADRASA|THERMAL_BATH)_DESCRIPTION$"`)。手本の選び方は下記
   2. 手本の文をコピーし、事実・数値・名詞を差し替える。名詞は`.claude/rules/game-terms.md`に従って公式訳を確認する
   3. 日本語固有の規則(`references/lang-jp.md`)を当てる
   4. **新しく書いた日本語は本人に確認してもらう**(内容の原本になるため)
3. **他言語に展開する(言語ごとに)**
   1. **語彙を先に確定する**: そのテキストで使うゲーム用語(Yield名・建造物名等)を、`.claude/rules/game-terms.md`に従ってその言語の公式訳として全部引き、用語一覧にする(ある言語の訳から類推しない)。このMod固有の名詞は`docs/glossary.md`から取る(無ければ本人に決めてもらい、`docs/glossary.md`に追記してから使う。日本語から勝手に訳さない)。**語彙は文を書く前に決める**: 後から用語を差し替えると、特に中国語では文の組み立てごと変わる
   2. 手本は手順2で選んだのと**同じLOCタグ**の、その言語の版を使う(`npm run lookup`は全言語を一度に出す)。その言語の手本が文の種類に合わない場合は、同じ種類の別の公式テキストを選び直してよい
   3. 事実シートの各行を、その言語の手本に当てはめて組み立てる。日本語文は見ない(見るのは日本語の意図を確認したいときだけ)
   4. 言語固有の規則を当てる: 英語は`references/lang-en.md`、中国語は`references/lang-zh.md`。**中国語の繁体字は簡体字からの機械変換ではなく、同じタグの繁体字版の手本から別に組み立てる**(語彙差があるため。`lang-zh.md` 1・3節)
4. **機械的に検査する**: `tools/loc-lookup`で`npm run check`(ゲーム本体を読まず高速に済ませたいときは`npm run check -- --no-terms`)。このMod自身の`Text/`の全言語について、次を検査する(実装は`validate-text.ts`/`validate-terms.ts`)
   - タグ集合の一致(全言語に全タグがあるか) — error
   - `[ICON_XXX]`・`[NEWLINE]`・`{1_Num}`等のプレースホルダーと、数字(数値)の集合が日本語と一致するか — error
   - 記号の言語別ルール(全角/半角・引用符・残留した仮名。`references/lang-*.md`) — warning
   - 日本語側で使った公式用語(`*_NAME`)に対応する、他言語の公式訳が本文に含まれているか — warning(ヒューリスティックなので偽陽性は目で判断する)

   errorは必ず直す。warningは1件ずつ実際の文を見て、直すか無視するか判断する。検査規則を増やす/直すときは`validate-*.ts`とこの節を一緒に更新する
5. **ブラインド逆翻訳で照合する**: 対象言語の文**だけ**(日本語も事実シートも見せない)を別のサブエージェントに渡し、効果・数値・対象・条件・制限を手順1の事実シートと同じ形式で書き出させる。返ってきたものを事実シートと突き合わせ、食い違い(過不足・意味のずれ・硬さの変化)を修正する。言い回しの一致は求めない。自分で書いた文を自分で照合するより、原文を知らない読み手のほうが誤りを客観的に検出できる
6. **本人確認**: 機械検査と逆翻訳で引っかかった点、固有名詞、手本に無い言い回しを使った箇所だけを見てもらう

## フレーバーテキストの多言語展開

外交台詞`LOC_DIPLO_*`等、キャラクターの性格・口調ベースのテキストは事実シートの対象ではない(効果を説明しないため)。手順は`implement-diplomacy-statements` Skillの「他言語への展開」に従う。ただし**文中のゲーム用語(使節団・大使館・国境開放等)は効果テキストと同じく手順3-1で公式訳を引く**。

## 言語共通の規則

### 手本の選び方

- **似た効果の公式テキストをコピーして数値・名詞だけ差し替えるのが最短ルート**。公式自身も`_EXPANSION1`/`_EXPANSION2`サフィックス違いのTraitで、ほぼ同一文・数値だけ差分という書き方を多用している。ゼロから言い回しを考えない
- **置き換え要素(UU/UD/UB/UI)の手本は、置き換え元の説明文ではなく、他文明の同じ種類の固有要素の説明文を選ぶ**。置き換え元の説明文をコピーすると、置き換え元の効果がすべて重複する(2026-09-27、シャチの水族館で実際にやってしまった)

### 固有要素(UU/UD/UB)の定型構文

公式のUD/UB全34件(`DistrictReplaces`/`BuildingReplaces`から抽出)のうち約20件と、UUを、ja/en/zh対訳で確認した(2026-09-22・09-27)。言語ごとの言い回しは各`references/lang-*.md`。

- **置き換え元に説明文(`DESCRIPTION`)がある場合、固有要素はその特殊効果のうち引き継ぐものを説明文に再掲する**(固有要素の説明文が置き換え元の説明文を置き換えて表示されるため、書かないとプレイヤーから見えなくなる)。公式の`BuildingReplaces`全18件のうち置換元に説明文があるのは工場・動物園・神殿の3種で、これを置換する4件はすべて再掲していた(2026-09-30、`tools/loc-lookup`で確認)。エレクトロニクス工場(工場置換)は「6タイル以内のすべての都心に及ぶ」「このボーナスは1つの都市に対して一度だけ適用され…」、温泉(動物園置換)は「6タイル以内の各都心に快適性…」と同じ「一度だけ適用」の文、スターヴ教会・プラサート(神殿置換)は「信仰力を使って使徒と審問官を購入するのに必要」(神殿の文の一部を短くして再掲)。置換元に説明文がない場合(大学・市場・銀行・円形闘技場など)は固有の効果だけを書く(マドラサ・航海術学校・トラクトリ等)。再掲する文は、置換元の公式説明文をそのままコピーする(アレンジしない)
- **UU**: 「このユニットは何を置き換えた固有ユニットか」を必ず最初に書き、「[文明]固有の…ユニット」という自己言及を省略しない
- **UD**: 「[文明]固有の区域。[置換元]に取ってかわる(、より安価に建設できる)。」に相当する文で始める。置換元(ウォーターパーク等)に説明文があるので、その文(「快適性を増やして人々の幸福の維持に貢献する」等)も上記のとおり公式のまま再掲する。設置の制限(「[区域]がある都市には建設できない」「礁には建設できない」等)は書く。**置換元と全く同じ制限でも省略しない**(公式の全ペアを機械的に比較して確認、2026-09-30: Hippodrome・Royal Navy Dockyard・Cothon・Bathは置換元と同一の制限文を書いており、Copacabanaも「礁には建設できない」を同一のまま書いている。固有区域の説明文は置換元の説明文を置き換えて表示されるため、書かないとプレイヤーから制限が見えなくなる)
- **UB**: 「[文明]固有の建造物。」に相当する文で始め、置換元の説明文があれば再掲したうえで、固有の効果を書く。「[置換元]に取ってかわる」は原則書かない(書いているのはプラサートだけ)

### 調査範囲の限界

言語別の文体調査(`references/official-*-text-style.md`)の対象はTrait説明文(日本語422件、英語・中国語198件)で、Civilopedia等の他のテキスト種別で同じ規則を直接検証したわけではない。明らかに違和感があれば、該当する種類の公式テキストで個別に確認すること。新しい種類で確認できた定型構文は、この節か`references/lang-*.md`に書き足していく。断片情報から仮説を積み上げがちな調査が必要になったら、先に`research-mod` Skillに従って一次情報を洗うこと。
