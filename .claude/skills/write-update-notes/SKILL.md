# write-update-notes

`main`と`develop`の差分から、プレイヤー向けの更新概要を4言語(日本語・英語・簡体字中国語zh_Hans_CN・繁体字中国語zh_Hant_HK、`Text/`配下の対応言語と同じ)で重要度順の箇条書きにまとめ、`docs/update-notes/<YYYY-MM-DD>.md`(作業日付)に書き出す。Steam WorkshopのMod更新公開(ModBuddyのUpload/Publish Updateダイアログ)には説明文と同じく言語別の更新ノート入力欄があるので、本人がそのファイルの内容を手動でコピペする。4言語分をチャットに書き出すと分量が多く読みにくいため、ファイルに固定してそこから参照する。

`docs/update-notes/*.md`は`.gitignore`済み(Git管理外)。毎回`main`/`develop`の実際の差分から作り直す使い捨て出力で、過去のリリース文面をリポジトリに残す設計ではない(`write-steam-description` Skillの`docs/steam-description/`と同じ考え方)。同名ファイルが残っていても古い内容を前提にせず、差分を取り直して書く。

## 手順

1. `git log main..develop --oneline`で、`main`にまだ取り込まれていないコミット一覧を取得する。
2. 各コミットを次の基準でふるいにかける:
   - **除外する**: `.claude/`配下のみの変更、Skill整備・調査メモ等プレイヤーに見えない`docs:`型、`refactor:`型(挙動を変えない前提のコミット)。
   - **候補に残す**: `feat:`/`fix:`型、および実際のゲーム内容(バランス・テキスト・アセット)に触れている変更。
3. コミットメッセージだけで内容が分からない、または影響範囲が不明な場合は`git show <hash>`で実際の差分を見て、プレイヤーにとって何が変わったのかを確認する。コミットメッセージの粒度をそのまま信用しない(実装都合で分かれているだけのことがある)。
4. 同じ機能・同じ対象についての複数コミットは1つの箇条書きにまとめる。
5. 以下の目安でプレイヤー視点の重要度順に並べる(見出しやカテゴリ分けはせず、フラットな順序付きリストにする):
   1. 新規実装コンテンツ(新しいリーダー/文明、固有ユニット・区域・施設・建造物の追加)
   2. バランス調整(既存能力の数値変更)
   3. 不具合修正(クラッシュ、意図しない効果、表示崩れなど)
   4. 新言語対応
   5. テキスト・言い回りの修正、軽微な調整
6. 日本語版を先に書く。他の3言語はそれぞれ日本語版からの翻訳として書く。`write-steam-description` Skillと同じ考え方で、能力名等の固有名詞は各言語の`Text/<lang>/Text.xml`にある公式ローカライズ済みの表記をそのまま使い、地の文は日本語版から翻訳する(ゼロから書き起こさない)。簡体字/繁体字は字体・語彙・句読点の違いがあるため、`write-official-zh-text-style` Skillの知見(あちらはゲーム内テキスト向けだが、字体・語彙の使い分け部分は流用できる)を踏まえて別々に書く(繁体字版を簡体字版の単純な字体変換で済ませない)。
7. `docs/update-notes/<YYYY-MM-DD>.md`(その日の日付。既に同日のファイルがあれば追記・更新する)に、4言語の見出しで区切って書き出す。ファイル冒頭に対象コミット範囲(`main`と`develop`それぞれのコミットハッシュ)を記録しておく(後から見返したときに何を集計した結果か分かるように)。
8. 書き出したファイルパスを本人に伝える。

## ファイルの構成(例)

```markdown
# 更新ノート 2026-09-22

対象: main(<mainのコミットハッシュ>) → develop(<developのコミットハッシュ)

## 日本語
- ...

## English
- ...

## 简体中文
- ...

## 繁體中文
- ...
```

## 注意

- 比較対象は実際の`main`・`develop`ブランチの現在のHEAD。ブランチ名や運用が変わっていたら(`.claude/rules/branching.md`参照)本人に確認する。
- このSkillの範囲は差分の分析・ファイルへの書き出しまで。Steam側への実際の反映や、`develop`から`main`へのマージ自体は行わない(マージの手順は`.claude/rules/branching.md`を参照。本人が別途ローカルで行う)。
